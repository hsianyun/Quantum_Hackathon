# Split Vault autonomous development workflow

This workflow guided the implementation run completed through Q14 on
2026-10-10. Document preparation preceded that authorized run. Read `AGENTS.md`, this file, `TASKS.md` and
`VERIFY.md` before starting. Preserve every `AGENTS.md` requirement; change a
conflicting feature plan rather than weakening the project instructions.

## Entry, eligibility and boundary

Use the existing isolated checkout; do not create a Git worktree unless the
user requests one. Inspect `git status` and preserve existing user changes.
Start at `B00`, then take tasks in `TASKS.md` order. A task is eligible only
if it is `TODO`, every listed dependency is `COMPLETE`, and it is within the
authorized scope. Mark it `ACTIVE` while working. An incomplete, `BLOCKED`
or `DEFERRED` prerequisite closes its descendants. `HUMAN_CHECK` needs actual
human/platform evidence; unrelated human checks do not block the explicitly
separate local tasks. No implementation task is active at the completed Q14 handoff.

Primary target: confirm baseline, complete Teleportation Calibration, implement
and verify Warden core/API/gameplay, then run full regression and review.
Only after all primary gates pass may the run implement QFT/inverse-QFT,
small periodic-state experiments, tests and a compatible JSON utility API.
Stop at `Q14`, or after the primary target if secondary work cannot proceed
safely. Record partial work and blockers honestly.

Do not proceed into full Quantum Radio visuals, Hidden Period gameplay, full
Circuit Architect, N=15 modular period finding, generic Shor, Final Vault,
distributed QFT/Tier B, multiplayer networking or a large visual redesign.
These require another review cycle. A roadmap is not implementation authority.
N=15 is deferred: `period.py` is empty and no controlled modular stage is verified.

## Architecture and autonomy

- HTML, vanilla JavaScript and root-level `main.css` only; local HTML references
  `./main.css`, with no second interface stylesheet or CSS import. Qiskit
  circuits, simulation, fidelity, Fourier mathematics and statistics stay in Python.
- Keep immutable game transitions separate from quantum calculations. No
  fabricated results or quantum calculations duplicated in JavaScript. Unit
  fixtures may isolate game rules; integration must exercise real Qiskit.
- Qollab runs the JS entry point. Use static named Python imports by root module
  name, such as `import { bell_experiment } from "api"`. Await `.callPromising(...)`
  or `.callPromisingKwargs(...args, { kwargs })`, then convert dictionaries with
  `.toJs({ dict_converter: Object.fromEntries })`. Reuse imported function/backend
  proxies and release owned returned proxies, including on conversion failure.
- Pass Qollab's injected selected `backend` for device execution. Do not replace
  it or silently fall back after an error. Identify ideal Python diagnostics
  accurately; exact statevector fidelity is not hardware tomography. Unsupported
  selected devices must fail clearly before spending resources.
- Repeated in-page trials use the documented local-simulator path. IonQ permits
  one job per Run; multi-step/multi-job features must not promise compatibility.
  No Flask, FastAPI, `server.py`, localhost services, `/api/...` endpoints, HTTP
  fallback, dynamic Python imports or assumed global Pyodide.
- All project/upload files remain flat at the root, at most 90. Count before
  every addition, including docs/tests/assets/configuration. Exclude local Git
  metadata, virtual environments, dependency caches and generated bytecode.
  Current implementation has 48 upload files; prefer updating existing files.
- The later run may edit repository files, add necessary flat files, refactor
  tested code, update docs/TASKS/VERIFY, run existing local tooling and fix its
  regressions. Install dependencies only in project `.venv`, preserving trust
  verification; keep helpers/caches within repository/workspace. Do not modify
  files outside this repository/workspace, global/system Python, global npm,
  Windows/system configuration or sandbox/security settings. No external
  push/publication without explicit authorization. Do not silently redesign
  previously working gameplay.

## Required feature contract

Before code, fill this contract under the task entry in `TASKS.md` and link
verification cases in `VERIFY.md`. Distinguish proposed APIs from existing ones.
An interface rendering is not completion.

| Field | Required decision |
| --- | --- |
| Quantum concept | Learning objective and physical experiment. |
| Alice's information | State/circuit/observations visible at each phase. |
| Alice's quantum reasoning | Meaningful decision and meaningful wrong alternative. |
| Bob's information | Independent useful information and what stays hidden. |
| Bob's quantum reasoning | Distinct decision requiring quantum knowledge. |
| Alice → Bob | Allowed information, encoding, timing and classical-bit cost. |
| Bob → Alice | Allowed information, encoding, timing and cost, including if none. |
| Resource cost | Credit/shot distinction, reservation/debit points, retries/reset. |
| Correct behavior | Circuit, analytic expectations, qubit/classical-bit ordering. |
| Incorrect decision | Physical consequence and state-dependent exceptions. |
| Success condition | Evidence, thresholds fixed before tests, reward/advancement. |
| Failure condition | Scientific failure versus transport/capability error; recovery. |
| Python API | Names, positional/keyword args, finite JSON schema, backend/diagnostics. |
| JavaScript/game modules | Transitions, adapters, role renderers and entry wiring. |
| Required tests | Quantum, correct/wrong player paths, ordering, errors, budgets, bridge, regression. |

Every new playable level follows Predict → Act → Exchange → Verify. Alice
and Bob each need quantum knowledge for an independent meaningful decision.
Require useful information exchange; one player telling the other which button
to press must not replace the second player's reasoning. Where practical,
give the roles different useful information. Shared-device role views are
educational separation, not secure multiplayer isolation. Keep revealing
measurements/answers/diagnostics hidden until the appropriate decisions are
committed. Wrong reasoning has an understandable quantum consequence, not just
"wrong." Review each of these requirements before marking a level complete.

## Lifecycle for every major feature

1. **INSPECT** — Read instructions, dependencies, relevant tests/source/API and
   current changes. Confirm the baseline, file count and runtime capabilities.
   Determine missing work; reuse completed Bell/teleportation foundations.
2. **DEFINE FEATURE CONTRACT** — Resolve every field above, API/backend scope,
   thresholds and independent test oracles before implementation. Record scope
   and intended modules under the task.
3. **IMPLEMENT QUANTUM CORE** — Reuse/extend real root-level Qiskit modules.
   Preserve public callers with additive changes. Model wrong operations
   physically, not as a UI flag.
4. **VERIFY QUANTUM CORE** — Test correct and physically meaningful incorrect
   behavior, explicit qubit and classical-bit order, backend/capability errors,
   JSON boundaries where applicable, and full existing regression.
   **NO gameplay may rely on an unverified quantum primitive.** If tests fail,
   stop later layers, diagnose and fix the quantum layer first.
5. **IMPLEMENT GAME LOGIC** — After step 4 passes, add pure transitions,
   commitments, exchange gates, costs, stale/replay protection, rewards,
   checkpoints/reset and advancement. No quantum calculations here. Register
   every new test in the real test commands.
6. **IMPLEMENT ALICE INTERACTION** — Implement her state/circuit/basis reasoning,
   commitments and permitted transmission with existing room/notebook helpers.
   Ensure her wrong decisions actually change the quantum experiment.
7. **IMPLEMENT BOB INTERACTION** — Implement independent recovery/statistical
   reasoning, commitment and permitted reply. No prefilled answer tables or
   Alice-only information that removes his task.
8. **INTEGRATE THROUGH EXISTING QOLLAB API** — Extend `api.py`,
   `quantum-client.js` and static imports in `main.js` while preserving existing
   signatures. Use async proxy conversion and real selected-device propagation.
   A tested quantum/API unit boundary may precede UI (Warden requires its
   wrapper first); gameplay still requires step 4. Extend server-free real-Qiskit
   stdio integration, never add an application server.
9. **TEST CORRECT PLAYER PATH** — Exercise real Python/Qiskit through the JS
   adapter into committed transitions: required exchange, correct quantum
   evidence, success, exactly-once cost/reward and advancement.
10. **TEST INCORRECT PLAYER PATH** — Test wrong quantum decisions, uncommitted
    actions, missing/invalid transmissions, malformed/stale/duplicate replies,
    errors/retries, exhausted budgets and fair reset. Explain the physics
    without early answer leakage.
11. **RUN FULL REGRESSION** — Run all commands in `VERIFY.md` and registered new
    suites. Preserve Bell Lock and original teleportation. Check exit statuses
    and actual executed counts; zero/skipped tests, mocks alone or syntax checks
    are not equivalent evidence.
12. **REVIEW** — Inspect diff for architecture/physics, both-player reasoning,
    required exchange, hidden answers, backend use, fairness, unchanged baseline
    behavior and file limit. Separate local from hosted/browser/hardware evidence.
    Do not silently fix an unrelated historical design gap.
13. **UPDATE TASKS.md** — `COMPLETE` requires contract, quantum gate, both player
    paths, full regression and review. Record exact commands/counts in VERIFY.
    Hosted checks remain `HUMAN_CHECK`. Persistent blockers need evidence and
    a concrete unblock action.
14. **CONTINUE OR STOP** — Select the next eligible authorized task, or stop at
    the boundary/no independent eligible work. Report last verified state,
    partial changes, blockers and pending human checks.

For backend-only QFT utilities, steps 5–7/player paths are explicitly not
applicable until a separate gameplay contract is authorized. Apply steps 1–4
and 8–14 with real API correct/incorrect-input checks. This exception cannot
be used to mark a playable level complete without game/UI verification.

## Handoff hazards

`VERIFY.md` records the original baseline and current implementation. `main.js`
now routes Bell Lock → Calibration → Warden through static Python imports.
`calibration.js` and `security.js` keep game transitions independent of quantum
physics; `later-level.js` reuses rooms/styles/notebook/channel. Warden and QFT
are implemented and tested. `radio.js` remains classical rendering, not a new
Quantum Radio level. `architect.js`, `period.py`, `verify.py` and
`test_period.py` remain empty and outside this run.

The existing teleportation batch API accepts Bob's correction **before**
sampling independent Alice outcomes. Calling it again after he sees the bits
samples a different experiment. Implemented calibration uses a verified staged Python
protocol: Alice commits a real Bell-measurement operation; Python measures
once and exposes only her bits; she transmits; Bob commits I/X/Z/XZ; Python
applies it to the same collapsed Bob state. Define a supported opaque
Python-owned trial handle or equivalent representation, binding state to
trial while keeping quantum state/calculations out of JS. Define lifecycle,
reset/replay checks and proxy ownership first. No density/fidelity/answer table
before Bob commits. Keep the existing batch API as a diagnostic.

The original batch teleportation API is ideal statevector simulation without
backend support; the staged calibration API additionally runs the selected
ideal simulator and conditions its Python state on that measured outcome.
Do not add an unused `backend` parameter and call that propagation. The new
contract must resolve supported local-simulator teaching mode versus device
execution. If no safe supported route is established, block staged gameplay
rather than claiming hardware fidelity or silently ignoring the Run selection.

Bell Lock passes its local contract, but completion does not require a message
and both rooms share a page. Historical completion does not prove the stronger
required-exchange design gate. Preserve the regression baseline and record
the separate `H03` review; no quiet overnight completion-rule redesign.

## Failure protocol

First attempt: inspect the exact command, exit status and failure; identify the
smallest likely cause; make the smallest correction; rerun affected tests.
Do not advance beyond a failed quantum gate.

Second attempt for quantum failures: inspect qubit/classical-bit order,
basis-change direction, control/target order, backend differences, shot and
statistical assumptions, and Qollab conversion. Add a diagnostic test if
useful; rerun affected checks and then full regression.

Persistent ambiguity/unsafe scope/unsupported capability: do not bypass it or
make a large architectural rewrite. Mark `BLOCKED` with reason, evidence and
unblock action. Preserve the last verified working state where practical;
continue only independent eligible tasks. Preserve user changes and describe
partial implementation honestly. Never delete valid failing tests, weaken
assertions for green tests, hard-code quantum answers or move physics into JS.

When an unavailable API becomes implemented, replace its stub expectation with
meaningful physics/API assertions and retain expectations for still-empty
modules. This contract update is not permission to delete inconvenient tests.
Human checks remain pending until actual supported platform evidence exists.
